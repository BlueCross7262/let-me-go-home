## 2. 목적 및 범위

### In-scope

- `src/date.js` 를 새로 만들고 `formatDate(value)` 를 export 한다.
- `formatDate` 는 입력을 `src/text.js` 의 `normalizeSpace` 로 다듬고 `new Date(...)` 로 읽는다.
- 읽은 날짜를 `toLocaleDateString(DEFAULT_LOCALE, { timeZone: 'UTC' })` 로 돌려준다.
  `DEFAULT_LOCALE` 은 `src/config.js` 에서 import 한다.
- 날짜로 읽을 수 없는 입력은 `RangeError` 를 던진다.
- `test/date.test.js` 에 `formatDate` 테스트를 더한다.

### Non-Goal

- NG-01 — `trimAll` 을 복원하지 않는다.
- NG-02 — `formatDate` 에 locale 인자나 다른 서식 옵션을 더하지 않는다.
- NG-03 — `src/config.js` 를 고치지 않는다.
- NG-04 — `src/text.js` 의 `normalizeSpace`·`slugify` 를 이 Phase 에서 고치지 않는다.

## 3. 기능 요구사항

- FR-01 — `formatDate` 는 ISO 날짜 문자열을 `DEFAULT_LOCALE` 날짜 서식 문자열로 돌려준다.
- FR-02 — `formatDate` 는 입력을 `normalizeSpace` 로 다듬은 뒤 읽는다.
- FR-03 — `formatDate` 는 시간대를 `UTC` 로 고정해 출력한다.
- FR-04 — `formatDate` 는 날짜로 읽을 수 없는 입력에 `RangeError` 를 던진다.
- FR-05 — `src/date.js` 는 `src/text.js` 의 `normalizeSpace` 와 `src/config.js` 의 `DEFAULT_LOCALE` 을 import 한다.
- FR-06 — `test/date.test.js` 는 `formatDate` 를 import 해 테스트한다.
- FR-07 (NG-01) — `src/`·`test/` 에 `trimAll` 식별자가 없다.
- FR-08 (NG-02) — `formatDate` 는 인자를 하나만 선언한다.
- FR-09 (NG-03) — `src/config.js` 는 바뀌지 않는다.
- FR-10 (NG-04) — `src/text.js` 는 바뀌지 않는다.

## 6. 예외 및 경계조건

- 앞뒤 공백이 있는 입력은 `normalizeSpace` 로 다듬은 뒤 읽는다.
